Hard Rock Concierge Flow

A chat concierge for Hard Rock Hotel Miami that checks bookings, makes bookings and reads the guest's Unity by Hard Rock points. The UI signs the guest in with ThunderID. Agent Manager's gateway checks their token. The agent never checks it: it only reads who the guest is and swaps the token for a narrow one before each MCP call.

Not yet confirmed in Agent Manager

  1. The gateway passes the user token to the agent. The agent reads Authorization or X-Forwarded-Authorization. If the gateway strips both, the agent answers 401.
  2. The agent identity may do token exchange. Agent Manager creates it (AMP_AGENTID_*). It needs the token-exchange grant and access to urn:hardrock:concierge-api.
  3. The audience the gateway expects. The UI's token is issued for urn:hardrock:concierge-api. The agent's protection in Agent Manager has to accept that.
  4. Binding member_id at the MCP layer. The MCP servers still trust the argument. Once mcp-auth forwards the exchanged token, a server or policy can check its sub against the member.
